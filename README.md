# minic-translator

Транслятор C-подібної мови, написаний на Flex і Bison. Лабораторна робота з
системного програмування.

Програма читає текст, будує абстрактне синтаксичне дерево і далі вміє
чотири речі: виконати програму, надрукувати дерево, перекласти код на C та
віддати дерево браузеру для малювання.

## Швидкий старт

~~~
brew install flex bison
export PATH="$(brew --prefix bison)/bin:$(brew --prefix flex)/bin:$PATH"
cd src && make
./lang ../examples/test3.lang
~~~

Якщо `bison --version` показує 2.3, це системна версія macOS. Потрібна 3.x
з Homebrew (вона keg-only, тому шлях додається в `PATH` вручну).

На Linux: `sudo apt install flex bison gcc make`.

Усі режими разом (інтерпретація, дерево, C, браузер): `./demo.sh examples/test3.lang`.

## Режими запуску

| Прапорець | Що робить |
|-----------|-----------|
| без прапорця | виконує програму |
| `--tree` | друкує AST текстом |
| `--c` | друкує еквівалентну програму на C |
| `--web` | друкує AST як JS-файл для `viewer.html` |

~~~
./lang --c ../examples/test3.lang > out.c && gcc out.c -o out && ./out
./lang --web ../examples/test3.lang > tree.js && open viewer.html
~~~

Візуалізації потрібен інтернет (d3.js береться з CDN). Колесо миші
масштабує, перетягування рухає дерево, клік по вузлу згортає гілку.

## Архітектура

~~~
            +-----------+   токени   +-----------+
  текст --> | lang.l    | ---------> | lang.y    | --> AST (Node)
            | (Flex)    |            | (Bison)   |
            +-----------+            +-----------+
                                                      |
              +---------------------+-----------------+
              |                     |                 |
        interp.c              codegen.c          ast_json.c
        виконання             текст на C         JSON для d3.js
~~~

Один парсер, одне дерево, три незалежні «споживачі». Додати нову ціль
(наприклад, інший мовний бекенд) означає написати ще один обхід дерева,
граматику чіпати не треба.

~~~
src/
  lang.l  lang.y          лексер і граматика
  ast.c   ast.h           вузол Node, конструктори, друк дерева
  interp.c                інтерпретатор
  codegen.c               генератор C
  ast_json.c              експорт для візуалізації
  viewer.html             d3.js
  main.c  Makefile
examples/                 test1, test2, test3
demo.sh                   показує всі режими підряд
~~~

## Мова

~~~c
int fact(int n) {
    if (n <= 1) { return 1; }
    return n * fact(n - 1);
}

double avg(double a, double b) {
    return (a + b) / 2;
}

int main() {
    int i;
    for (i = 1; i <= 5; i++) {
        print(fact(i));        // 1 2 6 24 120
    }
    int x = 7;
    print(x / 2);              // 3    (int / int)
    print(avg(3, 4));          // 3.5
    return 0;
}
~~~

Є типи `int`, `double`, `void`; функції з параметрами і рекурсією;
`if/else`, `while`, `for`; оператори `+ - * / %`, `< > <= >= == !=`,
`&& || !`; `i++` та `i--` як окремі оператори; вбудований `print(вираз)`;
коментарі `//` та `/* */`. Виконання починається з `main`.

Граматика повністю описана в `src/lang.y`. Головні правила:

~~~
func   : type IDENT '(' params ')' block
stmt   : simple ';' | call ';' | return [expr] ';' | print '(' expr ')' ';'
       | if '(' expr ')' stmt [else stmt]
       | while '(' expr ')' stmt
       | for '(' simple ';' [expr] ';' simple ')' stmt
       | block
simple : порожньо | type IDENT ['=' expr] | IDENT '=' expr | IDENT '++' | IDENT '--'
~~~

## Реальний вивід на `examples/test3.lang`

Інтерпретатор:

~~~
1  2  6  24  120  3  3.5  3.5  1  3      (кожне з нового рядка)
~~~

Фрагмент `--tree`:

~~~
FUNC int fact
  PARAM int n
  BLOCK
    IF
      BINOP <=
        VAR n
        NUM 1
      BLOCK
        RETURN
          NUM 1
~~~

Фрагмент `--c` (результат компіляції дає той самий вивід, що й інтерпретатор):

~~~c
#define PRINT(x) printf(_Generic((x), int: "%d\n", double: "%g\n"), (x))

int fact(int n) {
    if ((n <= 1)) {
        return 1;
    }
    return (n * fact((n - 1)));
}
~~~

## Рішення, які визначили реалізацію

**Один тип вузла.** Усе дерево складається зі структур `Node` з полями
`a, b, c, d` (діти) і `next` (наступний елемент списку). Так функції обходу
(друк, `eval`, генерація, JSON) мають однакову форму. Списки операторів,
аргументів, параметрів і функцій зв'язуються через `next`.

**Значення знає свій тип.** Інтерпретатор повертає пару «число + ознака int».
Завдяки цьому `7 / 2` дає 3, а `7.0 / 2` дає 3.5, як і в C. Присвоєння
приводить значення до типу змінної.

**Фрейм на кожен виклик.** Локальні змінні лежать у структурі `Frame`, яка
створюється при виклику функції. Через це рекурсія коректна, а `return`
передається вгору як ознака, що виходять з усіх вкладених циклів і блоків.

**`i++` розгортається в граматиці.** Правило створює вузол `i = i + 1`,
тому ні інтерпретатор, ні генератор окремого вузла для інкременту не мають.

**Лінивi логічні оператори.** `&&` і `||` не обчислюють праву частину, якщо
результат уже відомий, як і в C.

**`print` у згенерованому C.** Формат залежить від типу виразу, а повні типи
в генераторі не відстежуються. Тому `print(x)` стає макросом `PRINT(x)` на
основі `_Generic` з C11: компілятор C сам вибирає `%d` або `%g`.

**Прототипи.** Генератор спочатку виписує прототипи всіх функцій, тож їхній
порядок у вихідному файлі не має значення.

## Теорія у вигляді запитань

**Що роблять Flex і Bison?**
Flex перетворює регулярні вирази на скінченний автомат і ріже текст на токени.
Bison за граматикою будує таблиці LALR(1)-парсера і код функції `yyparse`,
яка викликає `yylex()` за кожним токеном. Лексер не вміє рахувати дужки,
для вкладеності потрібна контекстно-вільна граматика, тобто парсер.

**Як токен потрапляє з лексера в парсер?**
Лексер повертає номер токена, текст лежить у `yytext`, а значення (число
або ім'я) кладеться в `yylval`. Тип `yylval` описує `%union`.

**Що таке LALR(1)?**
Висхідний розбір зліва направо з одним токеном випередження. Парсер має
стек станів і на кожному кроці за станом та токеном вибирає дію: *shift*
(покласти токен на стек), *reduce* (замінити праву частину правила лівою
і виконати дію `{ ... }`) або *accept/error*. Через це дерево будується
знизу вгору: спочатку листки, потім батьки.

**Чим LALR відрізняється від LR(1) і SLR?**
LR(1) має найточніші, але найбільші таблиці. SLR компактний, але слабкий,
бо користується множинами FOLLOW. LALR зливає стани LR(1) з однаковим ядром:
таблиці майже як в SLR, потужність майже як в LR(1). Ціна: злиття може
створити reduce/reduce конфлікти, яких у LR(1) не було.

**Що таке shift/reduce конфлікт і як він розв'язується?**
У таблиці для пари (стан, токен) є і shift, і reduce. Розв'язання: порівнюють
пріоритет правила і токена; чий вищий, той і перемагає. При рівності
вирішує асоціативність (`%left` дає reduce, `%right` дає shift, `%nonassoc`
дає помилку). Без вказівок Bison обирає shift і попереджає.
Пріоритет правила дорівнює пріоритету його останнього токена або задається
через `%prec`; у нас так зроблено для `UMINUS` та `IFX`.

**Що таке reduce/reduce конфлікт?**
Два різні правила можна звернути в одному стані на одному токені. Bison
обирає правило, записане в граматиці раніше. Пріоритети тут не допомагають,
тож правильне рішення переписати граматику.

**Як розв'язано dangling else?**
У `if (a) if (b) x; else y;` не ясно, до якого `if` належить `else`. Це
shift/reduce на токені `ELSE`. Рядки `%nonassoc IFX` і `%nonassoc ELSE`
разом із `%prec IFX` у правилі `if` без `else` дають токену `ELSE` вищий
пріоритет, тому перемагає shift, і `else` прив'язується до найближчого `if`.

**Чи є конфлікти в цій граматиці?**
Ні. Перевірити можна так: `bison -v src/lang.y`, у файлі `lang.output`
слова `conflict` немає. Конфлікти легко відтворити, видаливши рядки
пріоритетів (див. нижче).

### Відтворення конфліктів

~~~
mkdir -p /tmp/conf && cd /tmp/conf
sed -e '/%nonassoc/d' -e 's/ %prec IFX//' ../src/lang.y > lang.y
bison -v -Wcounterexamples lang.y     # shift/reduce на токені ELSE
sed '/%left/d' ../src/lang.y > lang.y
bison -v lang.y                       # багато shift/reduce між операторами
~~~

## Перевірка

| Файл | Що перевіряє | Очікуваний вивід |
|------|--------------|------------------|
| `test1.lang` | змінні, `if`, `while` | `11`, потім `5 4 3 2 1` |
| `test2.lang` | факторіал циклом | `120` |

Для кожного тесту вивід інтерпретатора збігається з виводом скомпільованого
згенерованого C.

## Відомі обмеження

- Немає масивів, вказівників, структур, рядків, препроцесора.
- Немає `break`, `continue`, `+=`, глобальних змінних.
- `++` та `--` працюють лише як окремий оператор, не всередині виразу.
- В інтерпретаторі область видимості одна на функцію, а в C змінна з
  заголовка `for` бачиться лише в циклі.
- Ділення цілих на нуль у згенерованому C аварійно завершує програму,
  інтерпретатор лише повідомляє про помилку.
- Згенерований код потребує компілятора C11 (через `_Generic`).
